# DECISIONS — youtube-kit

> 근거나 배제 이유에 "미정"이 있는 항목은 선택만 확정됐고 이유는 아직 받지 않은 것이다.

## D-1. 개발 순서는 사용자 우선 top-down

**선택.** 사용 시나리오 → 노트북·CLI 사용 예 코드 → 함수·API·CLI 스켈레톤 → 구현 순서로
진행한다. 기존 `youtube_downloader` 코드는 마지막 구현 단계에서만 참고한다.

**근거.** 사용자가 실제로 칠 코드와 명령이 먼저 정해져야, 공개 함수·CLI의 형태가 사용
장면에서 나온다. 구현 편의가 인터페이스를 정하지 않는다.

**배제한 대안.** 기존 `youtube_downloader` 코드를 먼저 옮기고 그 위에 API·CLI를 얹는
bottom-up 방식. 기존 구조(대표 명령 하나에 옵션 조합으로 여러 시나리오를 처리하는 형태)가
그대로 물려져, BRIEF 1절의 불편이 되풀이된다.

## D-2. 기능별로 함수·명령을 나눈다

**선택.** 유스케이스 하나에 함수 하나, 함수 하나에 CLI 하위 명령 하나를 둔다 —
`info` · `video` · `audio` · `subtitle` · `batch`. CLI는 파이썬 API를 부르는 얇은 층이다.

**근거.** BRIEF 1절의 "명령 하나에 여러 일이 묶여 생긴 문제"(정보만 보려는 우회가 캐시를
지움, 자막과 무관하게 미디어를 받음, 종료 코드 하나가 두 결과를 표현)는 모두 한 명령이
여러 일을 하기 때문에 생긴다.

**배제한 대안.** 기존처럼 대표 명령 하나에 옵션 조합으로 여러 시나리오를 처리하는 통합
명령. 위 문제가 그대로 남는다.

## D-3. 포맷은 포맷 ID 문자열로만 지정한다

**선택.** `video()`는 영상·음성 포맷 ID, `audio()`는 음성 포맷 ID를 반드시 받는다.
기본값이 없고, 없는 ID면 실패한다.

**근거.** INTENT 3절 "판단하지 않고 주어진 조건대로 수행한다". 고를 재료는 `info()`가
준다.

**배제한 대안.**
- "최고 품질" 같은 기본값 — 품질 판단이다.
- yt-dlp 포맷 선택식(`bv*[height<=1080]+ba` 등) — 선택을 yt-dlp에 맡기는 것이라 원칙에
  어긋나고, 공개 인터페이스가 yt-dlp 문법에 묶인다.

## D-4. 자막은 `<종류>:<유튜브 키>` 트랙 ID로 지정한다

**선택.** 트랙 ID는 `manual:ko`, `auto:ko-orig`처럼 종류와 유튜브가 준 키를 잇는다.
`info()`는 트랙을 분류하지 않고 유튜브의 키와 이름을 그대로 보여준다.

**근거.** 같은 언어에 이름 붙은 트랙이 여럿이면 키가 `ko-1tAUxhK-Qig`처럼 붙고, 같은 키가
수동·자동 양쪽에 있을 수 있다. 종류를 붙여야 값 하나로 트랙이 정해진다.

**배제한 대안.**
- 언어 코드만으로 지정 — 트랙 하나를 가리킬 수 없다.
- 키를 보고 원본·더빙·번역으로 분류 — 더빙 영상에서 틀린다. 기존 `youtube_downloader`
  분류기가 셋을 모두 원본으로 오분류했다.

## D-5. 받은 그대로 저장한다

**선택.** 음성은 받은 포맷 그대로, 자막은 요청한 형식 그대로 저장한다. 자동 자막의 롤업
중복·시각 겹침도 정리하지 않는다.

**근거.** INTENT 4절 "변환과 정리". 다루는 방법은 호출하는 쪽이 정한다.

**배제한 대안.** 자동 자막 정리(중복 문장·시각 겹침 제거), 음성 형식 변환 — 호출하는
쪽이 할 판단을 대신한다.

## D-6. 호출하는 쪽이 준 폴더에 바로 저장한다

**선택.** `out_dir`에 바로 저장한다. 지정하지 않으면 현재 폴더다. 숨은 캐시를 두지 않는다.

**근거.** BRIEF 1절 — 캐시가 영상당 한 세대만 보관해 `--lang`을 바꾸면 앞서 받은 SRT를
덮어썼고, 정보 조회가 캐시를 바꾸며 받아 둔 SRT를 지웠다.

**배제한 대안.** 숨은 캐시 폴더에 받아 두고 복사해 내보내는 기존 구조.

## D-7. 영상 정보의 기준은 JSON 파일이다

**선택.** `info()`는 `<id>.meta.json`을 쓰고 같은 내용의 dict를 돌려준다. CLI
`info --json` 출력도 같다. 데이터 클래스를 두지 않는다.

**근거.** 표준 라이브러리만으로 읽고 쓸 수 있고, CLI `--json` 출력·job 파일(JSON Lines)과
형식이 같다.

**배제한 대안.** 데이터 클래스로 돌려주기 — 배제 이유 미정.

## D-8. `info()`는 매번 새로 조회하고, `out_dir`이 없어도 파일을 쓴다

**선택.** 부를 때마다 새로 조회해 파일을 덮어쓴다. `overwrite`를 받지 않는다.
`out_dir`이 없으면 현재 폴더에 저장한다.

**근거.** 포맷 ID는 바뀔 수 있으므로 파일에 든 값은 조회 시각 기준이어야 한다. 현재
폴더에 저장하는 근거는 미정.

**배제한 대안.**
- 이미 있는 `<id>.meta.json` 재사용 — 오래된 포맷 ID를 준다.
- `out_dir`이 없으면 파일 없이 dict만 돌려주기 — 배제 이유 미정.
- 함수는 dict만, CLI는 저장 — 배제 이유 미정.

## D-9. 파일명에 영상 ID와 요청 조건을 드러낸다

**선택.** SCENARIOS "저장 위치·파일명·재사용"의 표를 따른다. 예:
`<id>.<영상 ID>_<음성 ID>.<컨테이너>`, `<id>.<종류>.<유튜브 키>.<형식>`. 영문자·숫자·
`-`·`_`·`.`만 쓴다. 같은 이름이 있으면 재사용하고, 임시 이름으로 받은 뒤 바꾼다.

**근거.** BRIEF 1절 — `meta.json` 파일명이 고정이라 여러 영상을 같은 폴더로 받으면
덮어썼다. 조건이 다르면 이름이 달라야 서로 덮어쓰지 않는다.

**배제한 대안.**
- 두 포맷 ID를 `+`로 잇기 — URL에서 공백으로 해석되고 여러 도구가 특수문자로 다룬다.
- 트랙 ID의 `:`를 그대로 쓰기 — Windows 파일명에 쓸 수 없다.

## D-10. 실패를 다섯 종류로 나누고, 종료 코드 하나에 뜻 하나만 준다

**선택.** `InvalidInput`(2) · `VideoUnavailable`(3) · `NotAvailable`(4) ·
`MissingDependency`(5) · `YoutubeKitError`(1). 모두 `YoutubeKitError`를 상속한다.
일괄 수행의 부분 실패는 6이다.

**근거.** BRIEF 1절 — 종료 코드 하나가 자막 결과와 미디어 결과를 함께 표현해, 오디오를
받았는데도 종료 코드 4로 끝나 소비 측의 전사 폴백이 동작하지 않았다.

**배제한 대안.** 기존처럼 결과 여러 개를 코드 하나로 합쳐 표현하기.

## D-11. 일괄 수행은 순서대로, 개별 실패는 결과에 담는다

**선택.** 줄마다 URL 하나와 job(`video` · `audio` · `subtitle`) 하나. 순서대로 하나씩
수행하고, 실패한 줄이 있어도 나머지를 계속한다. 개별 실패는 예외가 아니라 결과에 담는다.
job에 `info`는 넣지 않는다.

**근거.** 무엇을 다시 시도할지는 결과를 보고 호출하는 쪽이 정한다. 일괄 수행은 선택이
끝난 뒤의 수행 단계다.

**배제한 대안.**
- 첫 실패에서 멈추기 — 재시도 판단을 호출하는 쪽에서 빼앗는다.
- 병렬 수행 — 이번 버전에서 하지 않는다(BRIEF 4절). 배제 이유 미정.

## D-12. 컨테이너는 `mp4` · `mkv`만 지정할 수 있다

**선택.** `container`는 `mp4` 또는 `mkv`. 그 밖의 이름은 `InvalidInput`. 지정하지 않으면
두 스트림이 mp4에 들어가는 코덱(영상 H.264 또는 AV1 + 음성 AAC)이면 mp4, 아니면 mkv.
지정한 컨테이너에 합칠 수 없으면 `NotAvailable`.

**근거.** 미지정 규칙은 코덱 호환성으로 결과가 하나로 정해지는 규칙이며 품질 판단이
아니다. 허용 목록을 둘로 한정한 근거는 미정.

**배제한 대안.**
- `webm`도 허용 — 배제 이유 미정.
- 지정 옵션 없이 고정 규칙만 — 배제 이유 미정.

## D-13. 라이브 방송 중인 영상은 받지 않는다

**선택.** 라이브 방송 중인 영상에 `video()` · `audio()`를 부르면 `NotAvailable`(4)로
실패한다. `info()`는 조회한다.

**근거.** 미정.

**배제한 대안.**
- 라이브 전용 예외와 종료 코드 — 배제 이유 미정.
- HLS로 현재 시점까지 받기 — 배제 이유 미정.
- 이번 버전에서 다루지 않기 — 배제 이유 미정.

## D-14. 다운로드 결과는 `{status, video_id, url, path}`, 모든 결과에 영상 ID와 URL

**선택.** `video()` · `audio()` · `subtitle()`은 `{status, video_id, url, path}`를
돌려준다. `batch()`의 `items`와 실패 시 `--json` 출력에도 `video_id`와 `url`을 담는다.

**근거.** SCENARIOS 입력 절 "모든 결과에 영상 id와 표준 url을 함께 담는다". 키 이름을
`video_id`로 둔 근거는 미정.

**배제한 대안.**
- 키를 meta와 같게 `id`로 통일 — 배제 이유 미정.
- 요청 조건(`video` · `audio` · `track` · `fmt`)까지 담기 — 배제 이유 미정.
- 성공 결과에만 id·url 담기 — 실패한 줄이 어느 영상인지 결과만으로 알 수 없다.

## D-15. `youtube_downloader`를 대체하고, 소비 측 전환은 다음 버전에 한다

**선택.** youtube-kit이 `youtube_downloader`를 대체한다. `youtube_library` 인제스트
전환은 다음 버전에 한다.

**근거.** 미정.

**배제한 대안.**
- 이번 버전에 전환까지 하기 — 배제 이유 미정.
- 대체 여부를 정하지 않고 병행 — 배제 이유 미정.

## D-16. SPEC을 두지 않는다

**선택.** `BRIEF` 완료 조건에서 `PLAN`으로 바로 간다. `docs/refs/SCENARIOS.md` ·
`docs/refs/SKELETON.md`는 참고 문서로 둔다.

**근거.** 미정.

**배제한 대안.** SCENARIOS의 확정 사항을 FR/NFR ID로 옮긴 SPEC — 배제 이유 미정.

## D-17. Phase는 층 순서로 나눈다

**선택.** 파이썬 API 전체 → CLI 전체 → 일괄 수행·README.

**근거.** 미정.

**배제한 대안.**
- 기능 순서(UC-1 → UC-3·4 → UC-2 → UC-5·CLI) — 배제 이유 미정.
- 유스케이스마다 함수와 CLI를 함께 — 배제 이유 미정.

## D-18. 반대 벤더 적대적 검증을 하지 않는다

**선택.** 필수 통과 Phase를 두지 않는다. 워크스페이스 규칙의 예외로 명시한다. 그 대신
바뀐 사용자 요청 API 인터페이스(`docs/refs/SKELETON.md`)와 주피터 노트북 검증(`notebooks\`,
PLAN 각 Phase의 완료 조건)으로 확인한다.

**근거.** 구현은 반대 벤더 적대적 검증을 이미 거친 기존 `youtube_downloader` 코드를
참고해 만든다(D-1). 기존 코드는 검증이 끝났으므로, 이번 버전에서 새로 확인할 것은 바뀐
인터페이스이고, 이는 노트북 검증으로 확인한다.

**배제한 대안.** 필수 통과 Phase와 Phase별 공격 초점을 정해 반대 벤더 검증을 다시 하기 —
검증이 끝난 기존 코드에 같은 검증을 되풀이하게 된다.

## D-20. 존재하지 않는 영상 ID는 `VideoUnavailable`로 알린다

**선택.** 형식은 맞지만 존재하지 않는 11자리 ID(T-19)는 조회 후 `VideoUnavailable`(3)로
실패한다.

**근거.** 3은 "영상 접근 불가"이고 이미 삭제된 영상을 포함한다. 존재하지 않는 ID도 결과적으로
그 영상을 얻을 수 없다는 뜻이며, YouTube가 삭제와 부재를 구별되는 응답으로 주지 않을 수
있어 둘을 나누면 구현이 추측으로 분류하게 된다.

**배제한 대안.**
- `NotAvailable`(4) — 4는 영상은 있는데 요청한 포맷·트랙·형식이 없다는 뜻이다. 넣으면 코드
  하나가 두 뜻을 갖는다(D-10).
- 별도 예외·종료 코드 — 삭제와 부재를 믿을 만하게 구별할 수 없다.

## D-19. 패키지 코드는 `src\` 바로 아래에 둔다

**선택.** `src\<패키지 이름>\` 폴더를 두지 않고 `src\` 아래에 `__init__.py` · `cli.py` 등을
바로 둔다. `pyproject.toml`이 `src\`를 패키지 이름 `youtube_kit`에 연결해, 부르는 방법은
`import youtube_kit as yk` 그대로다 (`docs/refs/STRUCTURE.md` 2절).

**근거.** 미정.

**배제한 대안.**
- `src\youtube_kit\` (src 레이아웃) — 배제 이유 미정.
- 루트에 `youtube_kit\`을 바로 두기 — 배제 이유 미정.
