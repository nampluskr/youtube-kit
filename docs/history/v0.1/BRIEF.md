# BRIEF — youtube-kit

## 1. 배경

지금은 `youtube_downloader`(`D:\projects\youtube_downloader`)를 쓴다. 이 도구는 CLI만
있고, 여러 시나리오를 대표 명령 하나의 옵션 조합으로 처리한다. 쓰면서 드러난 불편과
제한은 다음과 같다.

**쓰는 방법의 제한**

- 노트북에서 함수로 불러 결과를 바로 다룰 수 없다. 파이썬 API(`fetch`)가 있긴 하지만
  CLI와 같은 dict를 돌려줄 뿐이며, 자막이 없어도 예외 없이 상태값으로만 알린다.
- URL이 주어졌을 때 영상 정보와 받을 수 있는 내용(자막 트랙, 미디어 포맷)을 미리
  확인하는 방법이 없다.

**명령 하나에 여러 일이 묶여 생긴 문제**

- 정보만 보려면 `--source asr`로 우회해야 한다. 그런데 이 호출이 캐시를 "자막 없음"
  결과로 바꾸면서 이미 받아 둔 SRT를 지운다.
- `--media`는 자막 결과와 무관하게 미디어를 받는다. 자막이 있어도 받는다.
- 종료 코드 하나가 자막 결과와 미디어 결과를 함께 표현한다. 오디오를 제대로 받아도
  자막이 없으면 종료 코드 4로 끝나고, 소비 측(`youtube_library`의 인제스트)이 이를
  실패로 처리해 전사 폴백이 동작하지 않는다.
- 이미 받은 영상에 나중에 `--media`를 추가하면 정보 조회와 자막까지 다시 받는다.

**결과 보관의 제한**

- 캐시가 영상당 결과 한 세대만 보관한다. `--lang`을 바꿔 부르면 앞서 받은 언어의
  SRT를 덮어쓴다.
- `-o DIR`에서 `meta.json` 파일명이 고정이라, 여러 영상을 같은 폴더로 받으면 서로
  덮어쓴다.

**옵션의 의미가 흐려진 것**

- `--source manual`과 `--source auto`가 같은 동작을 한다.
- `--verbose`는 정의만 있고 효과가 없다.
- README의 런처 경로와 상위 문서 경로가 옛 위치(`d:\projects\tools\...`)를 가리킨다.

## 2. 이번 버전에서 풀고 싶은 문제

- 노트북에서 함수·API로 불러 쓸 수 있다.
- 다른 프로젝트나 도구에서 CLI로 불러 쓸 수 있다.
- URL이 주어졌을 때 영상 정보와 받을 수 있는 내용을 미리 확인할 수 있다.
- 정보 확인, 동영상 받기, 음성 받기, 자막 받기, 일괄 수행을 각각 따로 부를 수 있다.
  한 기능을 부를 때 다른 기능이 함께 실행되지 않는다 (DECISIONS D-2).
- 이 도구가 `youtube_downloader`를 대체한다.

## 3. 이전 버전에서 아쉬웠던 것

해당 없음 (v0.1)

## 4. 하지 않을 것

- 병렬 수행. 일괄 수행은 순서대로 하나씩 한다.
- `youtube_library` 인제스트를 이 도구로 전환하는 일. 다음 버전에 한다.
- 테스트 대상을 찾지 못한 조건의 검증: 연령 제한 영상, 예정된 라이브·프리미어, 삭제된 영상.

## 5. 완료 조건

- 노트북에서 `import youtube_kit as yk`로 정보 확인, 동영상·음성·자막 받기, 일괄 수행을
  모두 할 수 있다.
- `docs/refs/SCENARIOS.md`의 테스트 URL T-1 ~ T-20이 각 행의 기대 결과대로 동작한다.
- CLI 명령 5개(`info` · `video` · `audio` · `subtitle` · `batch`)가 내는 종료 코드가
  `docs/refs/SKELETON.md` 2.1 표와 일치한다.
- README에 설치법과 사용법이 있다.
