# 유스케이스 시나리오 — youtube-kit

## 원칙

youtube-kit은 **판단하지 않는다.** 정보 확인에서 영상·음성·자막에 대한 정보를 제공하고,
사용자나 다른 프로그램이 그 정보를 보고 입력 조건을 정한다. youtube-kit은 **주어진
조건대로 수행만** 한다.

- 대체(예: 한국어가 없으면 영어), 우선순위, 품질 선택을 하지 않는다
- 요청한 것이 없으면 다른 것으로 대신하지 않고 실패로 알린다
- 요청이 있으면 자동 번역 자막도 그대로 받는다

## 액터

| 액터 | 설명 |
|---|---|
| 사용자 | 주피터 노트북 등 파이썬 환경에서 함수·API로 직접 부르는 사람 |
| 다른 프로그램 | CLI 또는 함수·API로 부르는 다른 프로젝트·도구 |

## 입력

- **받는 입력.** 영상 URL, 재생목록 URL, 11자리 영상 ID. 재생목록 ID만 준 입력은 받지 않는다
- **정규화.** 입력은 받자마자 표준 URL로 바꾼다. 영상은 `https://www.youtube.com/watch?v=<ID>`,
  재생목록은 `https://www.youtube.com/playlist?list=<ID>`. `youtu.be/`·`shorts/`·`m.youtube.com`·
  `&t=` 같은 변형도 여기서 맞춘다. 형식에 맞지 않는 입력은 잘못된 입력으로 거부한다
- **출력.** 모든 결과에 영상 `id`와 표준 `url`을 함께 담는다
- **재생목록 URL**은 UC-1로 재생목록 정보와 영상 목록만 조회해 파일 하나로 저장한다. 들어 있는
  영상을 하나씩 조회하지 않는다. 호출하는 쪽이 목록에서 영상을 골라 영상마다 UC-1로 조회하고,
  URL 리스트 + job 리스트를 만들어 UC-5로 요청한다. youtube-kit이 재생목록의 영상에 조건을
  대신 정해 주지 않는다

## 유스케이스

| UC | 유스케이스 | 입력 조건 | 결과 |
|---|---|---|---|
| UC-1 | 정보 확인·저장 | URL | **영상 URL:** 영상 정보 파일 `<id>.meta.json` 하나. 영상의 존재·접근 가능 여부, 등록된 메타정보, 영상 포맷 목록(해상도·코덱·fps·크기), 음성 포맷 목록(코덱·비트레이트·크기·언어·원본/더빙·DRC), 자막 트랙 목록(트랙 ID, 수동/자동, 유튜브가 준 키와 이름, 제공 형식)을 담는다. **재생목록 URL:** 재생목록 파일 `<list-id>.playlist.json` 하나. 재생목록 정보와 영상 목록만 담는다. 어느 경우든 영상·음성·자막은 받지 않는다 |
| UC-2 | 동영상 다운로드 (소리 포함) | URL, 영상 포맷, 음성 포맷, 컨테이너(선택) | 영상과 음성을 합친 동영상 파일 하나 |
| UC-3 | 음성 다운로드 | URL, 음성 포맷 | 음성 파일 |
| UC-4 | 자막 다운로드 | URL, 자막 트랙 ID, 자막 형식(선택, 기본 `srt`) | 자막 파일. 요청한 트랙·형식이 없으면 실패 |
| UC-5 | 일괄 수행 | 영상 URL 리스트 + job 리스트 (줄마다 URL 하나와 job 하나가 짝을 이룬다. job은 UC-2~4 중 하나와 그 조건) | URL별 결과와 성공·실패 요약 |

- 흐름은 **조회 → 선택 → 수행**이다. UC-1이 선택지를 파일로 내놓고, 사용자나 툴이 그 파일을
  보고 고른 결과를 job으로 만들고, UC-2~5가 job대로 수행한다. 고르는 일은 youtube-kit 밖에 있다
- UC-2의 병합에는 ffmpeg가 필요하다
- 재생목록은 UC-1(재생목록) → 호출하는 쪽이 영상 선택 → UC-1(영상마다) → 호출하는 쪽이 job 결정
  → UC-5 순서로 처리한다

## 상세 시나리오 — 확정 사항

### 포맷 (UC-1 · UC-2 · UC-3)

- **포맷 ID는 필수다.** UC-2는 영상 포맷 ID와 음성 포맷 ID, UC-3은 음성 포맷 ID를 반드시
  받는다. "최고 품질" 같은 기본값을 두지 않는다. 없는 ID면 실패로 끝나고 다른 포맷으로
  대신하지 않는다
- **고를 재료는 UC-1이 준다.** `<id>.meta.json`의 포맷 목록에 포맷 ID가 들어 있다.
  youtube-kit은 목록을 거르거나 고르는 기능을 두지 않는다. 노트북에서는 `info()`가 돌려준
  dict(파일 내용과 같다)를 호출하는 쪽이 직접 거른다. CLI `info`는 포맷 ID가 든 표를
  출력하고, 다른 프로그램은 `<id>.meta.json`이나 `--json` 출력을 읽어 스스로 고른다
- **음성 포맷에는 언어·원본/더빙·DRC 여부를 함께 보여준다.** 더빙이 있는 영상은 같은
  포맷이 트랙별로 나뉜다(예: `140-0` 영어 더빙, `140-1` 한국어 원본). `-drc`는 음량 평준화
  변형이다. 어느 것을 받을지는 호출하는 쪽이 포맷 ID로 정한다
- **음성은 받은 포맷 그대로 저장한다.** 다른 형식으로 변환하지 않는다. 결과 확장자는
  고른 포맷의 확장자(m4a, webm 등)와 같다
- **동영상 컨테이너는 지정할 수 있다.** 지정하지 않으면 고정 규칙을 따른다 — 두 스트림이
  mp4에 들어가는 코덱(영상 H.264 또는 AV1 + 음성 AAC)이면 mp4, 그 밖의 조합이면 mkv.
  지정할 수 있는 이름은 `mp4` · `mkv`뿐이다. 코덱 호환성으로 결과가 하나로 정해지는
  규칙이며 품질 판단이 아니다. 지정한 컨테이너에
  합칠 수 없는 조합이면 실패로 끝낸다
- **yt-dlp 포맷 선택식(`bv*[height<=1080]+ba` 등)은 받지 않는다.** 선택을 yt-dlp에 맡기는
  것이라 원칙에 어긋나고, 공개 인터페이스가 yt-dlp 문법에 묶인다

사용 예:

```python
info = yk.info(url, out_dir="work")        # work/<id>.meta.json 저장, 같은 내용의 dict 반환
[f for f in info["video_formats"] if f["height"] == 1080]   # 1080p 포맷 목록
[f for f in info["audio_formats"] if f["ext"] == "m4a"]     # m4a 음성 포맷 목록
yk.video(url, video="137", audio="140", out_dir="work")
```

```
youtube-kit info <url>
youtube-kit video <url> --video 137 --audio 140 -o work
```

### 영상 정보 파일 (UC-1)

UC-1은 영상 하나에 `<id>.meta.json` 파일 하나를 만든다. 이 파일이 영상 정보의 기준이다.
`info()`의 반환값, CLI `info --json`의 출력, 파일 내용은 모두 같은 형태다.

- **파일 형식은 JSON이다.** 표준 라이브러리만으로 읽고 쓸 수 있고, CLI `--json` 출력·
  job 파일(JSON Lines)과 형식이 같다
- **부를 때마다 새로 조회하고 파일을 덮어쓴다.** 재사용하지 않는다. 포맷 ID는 바뀔 수 있으므로
  파일에 든 값은 조회 시각 기준이다. 오래된 파일의 ID로 받다가 UC-2~4가 `NotAvailable`로
  실패하면, 호출하는 쪽이 UC-1을 다시 불러 새 ID를 고른다

| 묶음 | 항목 |
|---|---|
| 식별 | 영상 ID, 표준 URL, 제목 |
| 채널 | 채널 이름, 채널 ID, 채널 URL |
| 시간 | 업로드일, 길이 |
| 내용 | 설명, 태그, 카테고리, 챕터(시작·끝·제목), 기본 언어 |
| 상태 | 공개 범위, 연령 제한, 라이브 여부 |
| 수집 기록 | 조회 시각, youtube-kit 버전, yt-dlp 버전 |
| 선택지 | 영상 포맷 목록, 음성 포맷 목록, 자막 트랙 목록 |

재생목록 파일 `<list-id>.playlist.json`은 재생목록 ID·표준 URL·제목·채널, 수집 기록, 영상
목록(영상 ID·표준 URL·제목)만 담는다. 영상별 포맷·자막은 담지 않는다 — 그것은 영상마다의
`<id>.meta.json`에만 있다. 여러 재생목록에 같은 영상이 있어도 영상 정보 파일은 하나다.

담지 않는 것: 통계(조회수·좋아요 수·댓글 수 — 조회할 때마다 바뀐다), 썸네일 URL.

### 자막 (UC-1 · UC-4)

- **자막은 트랙 ID로 지정한다.** 포맷 ID와 같은 방식이다. 언어 코드만으로는 트랙을 가리킬 수
  없다 — 같은 언어에 이름 붙은 트랙이 여럿이면 키가 `ko-1tAUxhK-Qig`처럼 붙는다
- **트랙 ID는 `<종류>:<유튜브 키>` 형태다.** 종류는 `manual` 또는 `auto`. 예: `manual:ko`,
  `manual:ko-1tAUxhK-Qig`, `auto:ko-orig`, `auto:en-US`. 같은 키(`ko`)가 수동·자동 양쪽에 있을 수
  있어서 종류를 붙여야 값 하나로 트랙이 정해진다
- **UC-1은 자막 트랙을 분류하지 않고 유튜브가 준 값을 그대로 보여준다.** 트랙 ID, 수동/자동,
  유튜브의 키와 이름(예: `ko-orig` "Korean (Original)", `en-US` "English (United States)").
  더빙이 있는 영상은 자동 자막에 원본 음성 인식, 더빙 음성 인식, 번역이 함께 나오며, 키만
  보고 코드로 분류하면 틀린다(기존 `youtube_downloader` 분류기가 셋을 모두 원본으로 오분류)
- **자막 형식은 선택 입력이고 기본값은 `srt`다.** 트랙마다 제공 형식은 UC-1이 보여준다.
  조사 시점(2026-09-26) 기준 모든 트랙이 `json3` `srv1` `srv2` `srv3` `ttml` `srt` `vtt`를 제공한다
- **받은 형식 그대로 저장한다.** 형식을 변환하지 않는다. 트랙이 제공하지 않는 형식을 요청하면
  실패로 끝나고 다른 형식으로 대신하지 않는다
- **자동 자막을 정리하지 않는다.** 롤업 중복과 단어 시각 태그는 `vtt`에만 있고, 유튜브가 주는
  `srt`에는 없다. `srt`에 남는 앞뒤 큐의 시각 겹침(두 줄 표시 때문)도 그대로 둔다. 다루는 방법은
  호출하는 쪽이 정한다

조사 근거 (`-pk2umNC-18` 한국어 자동 자막 `ko-orig`, 2026-09-26):

| 형식 | 큐 수 | 반복되는 문장 | 단어 시각 태그 | 앞 큐와 시각 겹침 |
|---|---|---|---|---|
| `srt` | 594 | 0 | 0 | 593 |
| `vtt` | 1187 | 있음 | 있음 | — |
| `json3` | 1187 | — | — | — |

```python
[t for t in info["subtitles"] if t["key"] == "ko"]            # 트랙 목록. 키 그대로 거른다
yk.subtitle(url, track="manual:ko", out_dir="work")            # 기본 srt
yk.subtitle(url, track="auto:ko-orig", fmt="json3", out_dir="work")
```

```
youtube-kit subtitle <url> --track manual:ko -o work
youtube-kit subtitle <url> --track auto:ko-orig --format json3 -o work
```

### 저장 위치·파일명·재사용 (UC-1 ~ UC-4)

- **저장 위치.** 호출하는 쪽이 준 저장 폴더(`out_dir`)에 바로 저장한다. 숨은 캐시 폴더에 받아
  두고 복사해 내보내는 구조를 두지 않는다. 폴더를 지정하지 않으면 현재 폴더에 저장한다
- **파일명.** 모든 파일은 영상 ID(재생목록 파일은 재생목록 ID)로 시작하고, 요청 조건이
  파일명에 드러난다. 조건이 다르면 파일명도 달라 서로 덮어쓰지 않는다

| 유스케이스 | 파일명 | 예 |
|---|---|---|
| UC-1 영상 정보 | `<id>.meta.json` | `-pk2umNC-18.meta.json` |
| UC-1 재생목록 | `<list-id>.playlist.json` | `PLyPc3E0Xm540Yfdln9qlVyyrqRME80jJm.playlist.json` |
| UC-2 동영상 | `<id>.<영상 포맷 ID>_<음성 포맷 ID>.<컨테이너>` | `-pk2umNC-18.137_140-1.mp4` |
| UC-3 음성 | `<id>.<음성 포맷 ID>.<확장자>` | `-pk2umNC-18.140-1.m4a` |
| UC-4 자막 | `<id>.<종류>.<유튜브 키>.<형식>` | `-pk2umNC-18.auto.ko-orig.srt` |

- **파일명 문자.** 영문자·숫자·`-`·`_`·`.`만 쓴다. `+`는 URL에서 공백으로 해석되고 여러 도구가
  특수문자로 다루므로 쓰지 않는다. UC-2의 두 포맷 ID는 `_`로 잇는다 — `-`는 포맷 ID 안에
  (`140-1`, `140-drc`), `.`는 파일명 구간 구분에 이미 쓰인다. 트랙 ID의 `:`는 Windows 파일명에
  쓸 수 없으므로 파일명에서는 `.`로 바꾼다
- **재사용 (UC-2 ~ UC-4).** 같은 이름의 파일이 이미 있으면 다시 받지 않고 결과에 재사용을
  표시한다. `overwrite`(CLI `--overwrite`)를 주면 다시 받는다
- **반쯤 받은 파일을 남기지 않는다.** 임시 이름으로 받은 뒤 완료되면 최종 이름으로 바꾼다.
  따라서 "파일이 있다 = 완성본이다"가 성립한다
- **UC-1은 재사용하지 않는다.** 부를 때마다 새로 조회해 파일을 덮어쓴다. `overwrite`를 받지 않는다

### 실패 구분 (UC-1 ~ UC-4)

| 실패 | 예 | 함수·API 예외 | CLI 종료 코드 |
|---|---|---|---|
| 잘못된 입력 | 형식이 틀린 URL·ID, 포맷 ID 누락, 없는 컨테이너 이름 | `InvalidInput` | 2 |
| 영상 접근 불가 | 비공개, 삭제, 존재하지 않는 ID, 지역·연령 제한 | `VideoUnavailable` | 3 |
| 요청한 것이 없음 | 이 영상에 없는 포맷 ID·트랙 ID·자막 형식, 지정한 컨테이너에 합칠 수 없는 조합 | `NotAvailable` | 4 |
| 실행 환경 부족 | UC-2에서 ffmpeg를 찾을 수 없음 | `MissingDependency` | 5 |
| 그 밖의 오류 | 네트워크 끊김, 다운로드 중단, 디스크 쓰기 실패 | `YoutubeKitError` | 1 |

- 모든 예외는 `YoutubeKitError`를 상속한다. 한꺼번에 잡을 수도, 종류별로 잡을 수도 있다
- **종료 코드 하나는 뜻 하나만 갖는다.** 성공은 0이다
- 2는 조회 전에 알 수 있는 오류, 4는 조회해야 알 수 있는 오류다. 4를 받으면 호출하는 쪽이
  UC-1로 다시 확인하고 다른 ID를 고른다
- `--json` 실행이 실패하면 `{"status": "error", "video_id": ..., "url": ..., "error": "<종류>", "message": "..."}`를
  출력한다. 종류 이름은 예외 이름과 같다. 영상 ID를 알 수 없는 입력이면 `video_id` · `url`은 `null`이다
- 라이브 방송 중인 영상은 UC-2 · UC-3에서 `NotAvailable`(4)로 실패한다. UC-1은 조회한다

### 일괄 수행 (UC-5)

- **실패한 URL이 있어도 나머지를 계속 수행한다.** 무엇을 다시 시도할지는 결과를 보고
  호출하는 쪽이 정한다
- **job은 UC-2~4(`video` · `audio` · `subtitle`) 중 하나다.** UC-1(`info`)은 넣지 않는다.
  일괄 수행은 선택이 끝난 뒤의 수행 단계이고, job은 `<id>.meta.json`을 보고 고른 결과다
- **줄마다 URL 하나와 job 하나가 짝을 이룬다.** URL마다 작업이 달라도 된다. 같은 영상에 작업을
  여럿 하려면(예: 음성과 자막) 같은 URL을 여러 줄에 쓴다
- **결과는 줄마다 하나씩, 입력과 같은 순서로 돌려준다.** 각 결과에 URL, 수행한 작업,
  상태(성공 / 재사용 / 실패), 성공 시 파일 경로, 실패 시 종류와 메시지를 담는다. 마지막에
  성공·재사용·실패 건수를 요약한다
- **개별 실패는 예외로 던지지 않고 결과에 담는다.** 예외는 일괄 입력 자체가 잘못됐을 때만
  던진다(`InvalidInput`, 예: URL 리스트와 job 리스트의 길이가 다름, job에 `info`가 있음)
- **순서대로 하나씩 수행한다.** 병렬 수행은 두지 않는다
- **입력 형태.** 함수·API는 URL 리스트와 job 리스트를 따로 받는다. CLI는 한 줄에 URL과
  job을 함께 쓴 job 파일(JSON Lines, `jobs.jsonl`) 하나를 받는다. job 파일은 사용자나 툴이
  youtube-kit 밖에서 만든다

| CLI 종료 코드 | 뜻 |
|---|---|
| 0 | 전부 성공 (재사용 포함) |
| 6 | 하나 이상 실패. 어느 것이 왜 실패했는지는 결과에 있다 |
| 2 | 일괄 입력 자체가 잘못됨 |

```python
yk.batch(urls, [{"do": "subtitle", "track": "manual:ko"},
                {"do": "audio", "audio": "140-1"}], out_dir="work")
```

```
youtube-kit batch jobs.jsonl -o work --json
```

`jobs.jsonl` (같은 영상에 두 작업):

### 조사에서 드러난 사실

- **포맷 ID의 번호(`-0`, `-1` …)는 언어나 원본 여부와 대응하지 않는다.** T-5는 `-0`이 더빙이고,
  T-6은 같은 한국어가 `140-9`와 `251-12`로 번호가 다르다. 음성 트랙은 반드시 UC-1의 목록에서 고른다
- **원본 표시(`original`)는 음성 트랙이 여럿일 때만 붙는다.** 트랙이 하나면 표시가 없다(T-7 ~ T-13)
- **자동 자막의 `-orig`는 원본 음성을 뜻하지 않을 수 있다.** T-6은 더빙 언어마다 `-orig`가 붙는다
- **`-drc`(음량 평준화)와 `-sr`(AI 업스케일) 변형 포맷이 있다**
- **4K는 H.264가 없고 VP9·AV1뿐이다.** 4K를 mp4로 받으려면 AV1 + AAC 조합을 고른다
- 조사한 120편 모두 영상과 음성이 합쳐진 포맷이 없었다 (라이브의 HLS 제외)
